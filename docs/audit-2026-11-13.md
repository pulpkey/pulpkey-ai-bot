- Group access now fails closed when no WhatsApp group allowlist is configured.
- Direct-message replies are disabled by default and require both an explicit
  opt-in and a reviewed phone allowlist.
- Proactive idempotency keys persist across bridge restarts.
- Empty employee audiences skip work-log broadcasts instead of creating
  untrackable requests.
- Automation metrics distinguish sent, skipped and duplicate runs.
- Completed work-log cycles close cleanly without being labelled followed up.
- Follow-up failures are counted without crashing the scheduler.
- Recurrence preserves local wall-clock time through daylight-saving changes.
- Fake production roster entries and inherited product naming were removed.
- Production dependency audits report zero known vulnerabilities.

## Operational boundary

The WhatsApp transport uses a linked account through Baileys because the
official WhatsApp Business API does not support this group-member workflow.
This remains an account-policy risk and must use a dedicated company number.
Production activation still requires reviewed credentials, a real group JID,
verified Pulpkey data and an end-to-end test in an isolated WhatsApp group.
